# OS-027 — fronteira de captura exclusivamente manual do Mercado Livre

Estado: **PREPARADA**. Origem: esclarecimento do proprietário no [mapa](../diagnosticos/fluxo-unico/MAPA.md#0-entradas-e-atualização). Baseline: `main` `43700c59` mais alterações locais preexistentes; comparar diff dos caminhos antes de escrever. Porte crítico por acesso externo e execução em GitHub.

**Objetivo observável:** operador captura/recaptura ML somente ao navegar e escolher a oferta; nenhuma rota, lote novo/antigo ou worker tenta coleta automática ML. Shopee/AliExpress continuam captura por API e cron de reconsulta por ID. Após persistência, os três canais entram na mesma triagem de catálogo, conforme evidência disponível. Não objetivos: contornar bloqueios do ML, retirar histórico, desligar APIs de Shopee/AliExpress, alterar quotas, migrar dados ou disparar workflow real.

**Protegidos:** `.github/workflows/monitor-prices.yml`, `.github/workflows/capture-offers.yml`, `packages/persistence/bin/sweep.ts`, migrations, credenciais/env, rotas de captura manual/extensão, ordens e resultados anteriores. Se uma rota adicional ainda permitir disparo ML, registrar `BLOQUEIO_DE_FRONTEIRA` e revisar a OS antes de alterá-la.

**Contrato:** `batchCapturePlan` aceita somente Shopee/AliExpress. Pedido explícito de ML por endpoint de lote recebe erro seguro `manual_capture_only`; não o remove silenciosamente de um lote misto. `/api/admin/rodagem` informa o mesmo destino manual sem criar lote. Worker rejeita ou encaminha para retomada humana um lote ML legado **antes** de invocar `runStep(capture)`; nunca ativa flags ML. Lote misto legado pode concluir lojas API sem marcar ML como capturado; status e motivo permanecem honestos. Captura manual/extensão preserva autorização, tenant, provenance e trilha de observação. O cron existente continua restrito a Shopee/AliExpress.

**Aceites**

- AC-027.1: POST autenticado tentando ML, isolado ou misto, não cria nova execução ML nem dispara GitHub; retorna instrução manual e não expõe credenciais. Falta de sessão/conta segue 401/403 existentes.
- AC-027.2: lote legado com ML e consentimento verdadeiro chama `runStep(capture)` zero vezes para ML; recupera fase/erro verificável sem loop. Shopee/AliExpress do mesmo lote continuam uma vez cada e triagem não usa ML ausente como sucesso.
- AC-027.3: captura humana de ML ainda persiste produto/observação e passa à triagem elegível; monitoramento periódico continua sem ML.

**Verificação:** `npm test --prefix packages/web`; `npm run test:capture-batch --prefix tools/editorial-tests`; `npm test --prefix tools/editorial-tests`; `npm run typecheck --prefix packages/web`; teste de rota com injeção de transporte sem rede e fixture de lote legado. Validar resposta e contagem de chamadas, não apenas compilação. Sem operação remota autorizada. Risco: lotes antigos aguardarem intervenção; rollback do delta local só após garantir que a captura automática não seja reativada.

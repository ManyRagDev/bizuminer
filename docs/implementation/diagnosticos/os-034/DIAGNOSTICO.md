**Limite de observabilidade de BUG-021:** a fixture atual muda `product_curation.status` por SQL direto, sem escrever `curation_event`. Depois de `rejected→approved`, o estado final é indistinguível de uma conta que nunca foi rejeitada, se nenhum evento/timestamp confiável foi gravado. Exigir que uma leitura detecte esse histórico apagado demandaria outra fonte persistida ou trigger, fora do escopo atual. O teste de fechamento deve realizar transições pelo caminho real `reviewProduct`, que grava `curation_event`; SQL direto continua útil para verificar bloqueio enquanto o status está rejeitado, mas não para afirmar memória de uma transição não registrada. Isso é uma limitação do **diagnóstico de teste**, não dispensa a regra contratual para operações suportadas.

**Relação entre achados:** ambos deixam opcional ou perdem informação necessária para validar uma decisão anterior; as causas de implementação são distintas. BUG-018 (versão da regra de catálogo) e BUG-020 (justificativa copiada da alegação) são pendências pontuais confirmadas pela auditoria, incorporadas à OS-036 por compartilharem os módulos de seleção. A “recaptura real” de AC-028.1 ainda não está provada pela fixture PGlite, que escreve SQL direto; `ingest.test.ts` cobre reingestão em memória. Não há defeito novo de unicidade demonstrado. BUG-017/022/023 permanecem fechados na evidência local.
